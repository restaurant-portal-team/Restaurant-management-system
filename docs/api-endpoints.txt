RESTAURANT MANAGEMENT PORTAL — API ENDPOINTS REGISTER
Version: 1.0 | API prefix recommendation: /api/v1 (confirm before implementation)

RULES
- This is a living API contract. Claude updates it during EVERY approved feature that creates, modifies or consumes an API.
- Status per endpoint: PLANNED or IMPLEMENTED; never claim IMPLEMENTED without backend code and verification.
- Record all endpoints used by frontend, including auth, staff, menu, recipes, inventory, orders, kitchen, waiter, tables, payments, dashboard and alerts.
- Document method, path, feature ID, role/auth, request DTO and validation, response shape, error codes, backend module/controller, frontend caller/page, status, tests and notes.
- Avoid inventing endpoints as completed. Paths below are DRAFT candidates subject to approval.
- Owner-only operations must be guarded server-side; customer order visibility scoped to own order or secure guest lookup.
