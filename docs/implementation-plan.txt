CROSS-FEATURE BUSINESS RULES
- Order status: PENDING -> PREPARING -> READY -> SERVED; cancellation rules require explicit approval.
- Stock deducted ONLY on authorized transition PENDING -> PREPARING; exactly once in atomic DB transaction.
- Insufficient ingredients block transition and leave order PENDING. Never allow negative inventory.
- A customer never sees private recipes, ingredient stocks, costs, or staff-only data.
- Payment status separate from order status: SERVED can remain UNPAID.
- Low-stock active if stock <= minimum; healthy only if stock > minimum. Stock zero is OUT_OF_STOCK.
- Single order record in PostgreSQL; role portals show filtered views, not copied orders.
- Customer ordering mode (guest vs login, QR vs verified table) must be approved before F11.
- Preserve tasteful motion, responsive layouts, accessibility and reduced-motion preferences.
